Реализуй фичу автоматически в Go проекте:

**Требования:**

- Применяй ВСЕ правила Go разработки из архитектуры проекта
- Выполняй фичу полностью автоматически без остановок
- Создавай только то, что реально используется (принцип YAGNI)
- Следуй принципам Clean Architecture
- Применяй все правила кодирования:
  - Все функции с явными типами возвращаемых значений
  - Современный Go синтаксис (Go 1.22+)
  - БЕЗ КОММЕНТАРИЕВ в коде (код должен быть самодокументируемым)
  - Go naming conventions
  - **КРИТИЧЕСКИ ВАЖНО: Принцип YAGNI** - создавай ТОЛЬКО те функции, компоненты, методы и утилиты, которые реально используются в текущей задаче
  - Все строки на английском языке
  - Следование Clean Architecture принципам

**Шаги выполнения:**

1. **ОБЯЗАТЕЛЬНО:** Изучи текущую архитектуру проекта:
   - Прочитай файл `.cursor/rules/project-architecture.mdc`
   - Пойми структуру проекта и принципы Clean Architecture
   - Определи какие компоненты будут затронуты фичей

2. **Анализ задачи** - определи что именно нужно реализовать
3. **Планирование** - определи какие файлы нужно создать/изменить по слоям Clean Architecture
4. **Реализация** - создай/измени все необходимые файлы:
   - **Models** (`internal/models/`) - доменные модели
   - **Repositories** (`internal/repositories/`) - слой доступа к данным
   - **Services** (`internal/services/`) - бизнес-логика
   - **HTTP Handlers** (`internal/http/`) - HTTP слой
   - **Middleware** (`internal/http/`) - middleware (если нужен)
   - **Tests** - тесты для каждого слоя
   - **Migrations** (`migrations/`) - SQL миграции (если нужны)
5. **Проверка** - запусти golangci-lint, go vet и тесты
6. **Финальная проверка** - убедись что все работает

**Правила реализации:**

- Используй существующую архитектуру проекта
- Следуй принципам Clean Architecture
- Создавай только то, что реально используется (YAGNI)
- Используй dependency injection через конструкторы
- Используй context.Context для request-scoped данных
- Обрабатывай ошибки правильно
- Пиши тесты для каждого слоя
- Используй существующие middleware и утилиты

**Формат отчёта:**

```
🚀 Фича: [название]

✅ Анализ: [что делаем]
✅ Планирование: [какие файлы создаём/изменяем]
✅ Реализация: [что создано/изменено]
✅ Проверка: [результаты линтера и тестов]
✅ Готово: [фича полностью реализована]

Созданные/изменённые файлы:
- [файл 1] - [описание изменений]
- [файл 2] - [описание изменений]
```

**Важно:**

- Выполняй ВСЕ шаги подряд без остановок
- НЕ создавай лишний код "на будущее"
- Используй только то, что реально нужно для текущей задачи
- Всегда проверяй что код компилируется без ошибок
- Применяй все правила из архитектуры проекта

**Примеры фич для Go проекта:**

- Добавление нового API endpoint
- Реализация нового middleware
- Добавление новой доменной модели
- Интеграция с внешним API
- Добавление кеширования
- Улучшение безопасности
- Оптимизация производительности

**Команды для проверки:**

```bash
# Линтер
golangci-lint run

# Go vet
go vet ./...

# Тесты
go test ./... -count=1 -race -timeout=60s

# Форматирование
gofumpt -l -w .
goimports -w .
```
