Выполни план разработки фичи пошагово в Go проекте:

**Требования:**

- Прочитай план из папки `docs/`
- Следуй принципам Clean Architecture
- Выполняй шаги последовательно по слоям архитектуры
- **ВАЖНО: После каждого шага с изменениями в коде ОБЯЗАТЕЛЬНО спрашивай подтверждение перед переходом к следующему**
- Применяй все правила Go разработки:
  - Все функции с явными типами возвращаемых значений
  - Современный Go синтаксис (Go 1.22+)
  - БЕЗ КОММЕНТАРИЕВ в коде (код должен быть самодокументируемым)
  - Go naming conventions
  - **КРИТИЧЕСКИ ВАЖНО: Принцип YAGNI** - создавай ТОЛЬКО те функции, компоненты, методы и утилиты, которые реально используются в текущей задаче
  - Все строки на английском языке
  - Следование Clean Architecture принципам

**Шаги:**

1. **ОБЯЗАТЕЛЬНО:** Изучи текущую архитектуру проекта:
   - Прочитай файл `.cursor/rules/project-architecture.mdc`
   - Пойми структуру проекта и принципы Clean Architecture
   - Определи какие компоненты будут затронуты планом

2. Найди и прочитай указанный план в папке `docs/`
3. Проверь соответствие плана принципам Clean Architecture
4. Покажи список всех шагов из плана
5. Начни выполнение первого шага:
   - Реализуй шаг полностью согласно Clean Architecture
   - Покажи что было сделано
   - **Если были изменения в коде, спроси подтверждение: "Шаг [N] завершён. Перейти к шагу [N+1]?"**
   - Дождись ответа пользователя (только при наличии изменений в коде)
6. Переходи к следующему шагу ТОЛЬКО после подтверждения (при наличии изменений в коде)
7. Повторяй пункт 5-6 для каждого шага
8. После завершения всех шагов:
   - Запусти golangci-lint и go vet
   - Запусти тесты: `go test ./... -count=1 -race -timeout=60s`
   - Покажи итоговый статус выполнения плана
9. **АВТОМАТИЧЕСКИ** (без подтверждения пользователя) выполни финальную проверку:
   - Убедись, что все пункты плана выполнены
   - Удали файл плана из папки `docs/`

**Порядок реализации по слоям Clean Architecture:**

1. **Models** (`internal/models/`) - доменные модели
2. **Repositories** (`internal/repositories/`) - слой доступа к данным
3. **Services** (`internal/services/`) - бизнес-логика
4. **HTTP Handlers** (`internal/http/`) - HTTP слой
5. **Middleware** (`internal/http/`) - middleware (если нужен)
6. **Tests** - тесты для каждого слоя
7. **Migrations** (`migrations/`) - SQL миграции (если нужны)

**Формат отчёта после каждого шага:**

```
✅ Шаг [N]: [название шага]

Выполнено:
- [действие 1]
- [действие 2]

Созданные/изменённые файлы:
- [файл 1]
- [файл 2]

Готов перейти к следующему шагу?
```

**Правила реализации:**

- Используй существующую архитектуру проекта
- Следуй принципам Clean Architecture
- Создавай только то, что реально используется (YAGNI)
- Используй dependency injection через конструкторы
- Используй context.Context для request-scoped данных
- Обрабатывай ошибки правильно
- Пиши тесты для каждого слоя
- Используй существующие middleware и утилиты

**Важно:**

- НЕ выполняй несколько шагов подряд без подтверждения (кроме финальной проверки)
- **Подтверждение требуется ТОЛЬКО при наличии изменений в коде**
- Давай пользователю возможность проверить результат каждого шага с изменениями
- Если пользователь попросит изменения - внеси их перед переходом к следующему шагу
- **ИСКЛЮЧЕНИЯ:**
  - Шаги без изменений в коде выполняются без подтверждения
  - После успешной проверки линтера и тестов автоматически выполни финальную проверку и удали файл плана
