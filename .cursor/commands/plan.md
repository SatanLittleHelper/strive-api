Создай план для разработки фичи в Go проекте:

**Требования:**

- План сохраняется в папку `docs/`
- Название файла: `[feature-name]-[brief-description].md`
- Структурированный и детальный план
- Следование принципам Clean Architecture

**Структура плана:**

1. **Overview**
   - Краткое описание фичи
   - Цели и задачи
   - Ожидаемый результат
   - API endpoints (если применимо)

2. **Technical Requirements**
   - Необходимые компоненты по слоям архитектуры:
     - **Models** (`internal/models/`) - доменные модели
     - **Services** (`internal/services/`) - бизнес-логика
     - **Repositories** (`internal/repositories/`) - слой доступа к данным
     - **HTTP Handlers** (`internal/http/`) - HTTP слой
     - **Middleware** (`internal/http/`) - middleware
   - Зависимости от внешних сервисов
   - Конфигурация через ENV переменные

3. **File Structure**
   - Список файлов которые нужно создать/изменить
   - Организация в папках проекта согласно Clean Architecture
   - Миграции БД (если нужны)

4. **Implementation Steps**
   - Пошаговый план реализации по слоям:
     1. **Models** - создание доменных моделей
     2. **Repositories** - слой доступа к данным
     3. **Services** - бизнес-логика
     4. **HTTP Handlers** - HTTP слой
     5. **Middleware** - middleware (если нужен)
     6. **Tests** - тесты для каждого слоя
   - Приоритизация задач
   - Зависимости между шагами

5. **Database Changes**
   - SQL миграции (если нужны)
   - Изменения в схеме БД
   - Индексы и ограничения

6. **API Design**
   - HTTP endpoints
   - Request/Response модели
   - Коды ответов
   - Валидация входных данных

7. **Testing Strategy**
   - Unit тесты для каждого слоя
   - Integration тесты для API endpoints
   - Test cases и edge cases
   - Моки для внешних зависимостей

8. **Security Considerations**
   - Аутентификация и авторизация
   - Валидация входных данных
   - CORS настройки
   - Rate limiting
   - Security headers

9. **Considerations**
   - Потенциальные проблемы
   - Best practices для Go
   - Performance considerations
   - Error handling

**Шаги:**

1. **ОБЯЗАТЕЛЬНО:** Изучи текущую архитектуру проекта:
   - Прочитай файл `.cursor/rules/project-architecture.mdc`
   - Пойми структуру проекта и принципы Clean Architecture
   - Определи существующие компоненты и их взаимодействие

2. Проанализируй требования к фиче
3. Изучи архитектуру проекта (`docs/` и `internal/` структуру)
4. Определи какие слои Clean Architecture затронуты
5. Создай детальный план следуя структуре выше
6. **ОБЯЗАТЕЛЬНО:** Учти влияние фичи на архитектуру:
   - Какие новые компоненты потребуются
   - Какие существующие компоненты нужно изменить
   - Как фича впишется в текущую архитектуру
   - Какие изменения потребуются в файле архитектуры
7. Сохрани план в файл `docs/[feature-name].md`

**Примеры фич для Go проекта:**

- Добавление нового API endpoint
- Реализация нового middleware
- Добавление новой доменной модели
- Интеграция с внешним API
- Добавление кеширования
- Улучшение безопасности
- Оптимизация производительности

Создай план и сохрани его в соответствующий файл.
